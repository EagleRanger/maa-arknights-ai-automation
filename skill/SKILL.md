# 明日方舟自动化

按用户已经确定的任务和资源设置执行。配置文件记录“要做什么、能花什么”，不是要求每张新页面都重新申请许可。不要为方便测试擅自改变关卡、玩法或资源用途。

## 脚本正常做，卡住时 AI 接着做

分清三件事：奖励/战斗等是否真的完成、现在是什么页面、能不能继续下一步。识字错误或弹窗陌生，不等于整日日常失败，更不等于应该关闭游戏。

1. 成熟步骤直接交脚本执行。脚本尝试恢复后仍不会处理（当前实现最多三轮），保留游戏、MAA、模拟器和正在等待的脚本，把最新截图交给执行 AI。用户指定的截止时间或停止要求仍然有效。
2. AI 先看图，再通过已有后台点击方法处理。页面上还有未完成的排版、领奖等内容时，先处理它，不要一律退回首页。普通返回、关闭、确认等已在任务范围内的操作，不用等待项目重新写代码或让用户重复授权。
3. 做完实际操作，重新截图确认，再通知原脚本继续。**写“继续”或提交结果文件不会替你点击游戏。** 如果仍是错误页，不能把它报成首页。
4. 查看原脚本是否继续了刚才那一步。回到首页只证明导航恢复；领奖要看已领取标记/数量变化，战斗要看实际结算。不能用“回到首页”代替“日常完成”。
5. 某个可选活动暂时处理不了，保留未完成说明；恢复到能继续操作的页面后，做其余独立任务。本次任务的调用方决定下一模块和最终退出，不让单个小模块一报错就关掉全套程序；单项任务也不必启动整日日常来收尾。

详细做法见[中断续跑、更新与签到](references/continuity-and-signin.md)。反复出现的代码错误或功能缺口交项目修复；正常运行时不需要两个 AI 同时盯同一份日志。

日常截图检查、页面判断和接回操作由执行流程完成。项目负责关键结果监督和解决执行确实处理不了的问题，不重复逐张看图，也不要求普通点击先交项目审批。

## 不依赖特定模型厂商

本说明供不同厂商的 AI 使用，不依赖 OpenAI 的聊天记忆或专用工具名。接收方需能运行本地命令、查看截图，并使用已接好的后台控制工具；缺哪项就明确报告哪项，不假装已经执行。

PTC不是运行依赖；工具调度出错时可先用标准模式排查。软件路径、Python/OCR或本机配置缺项应在接入检查中补齐，不据此要求用户更换模型。

- “执行 AI”就是当前负责操作游戏的对话；“项目 AI”负责修改代码。两者可以是同一个对话，不要求另外创建对话。
- “控制器/owner”是正在操作这一个游戏实例的脚本。不要再开第二个脚本和它抢着点击。
- “run_id / event_id”分别标识本次运行和当前卡住的问题；从当前运行记录读取，不自己编造。
- “回执/recheck”是通知原脚本重新检查的结果，不是点击命令，也不是任务完成证明。
- 跨对话工具按接收平台实际提供的接口调用。没有该功能就在当前执行对话接手，不把 Codex 工具名当成游戏恢复的必备条件。

## 我们的脚本、MAA 和模拟器各做什么

日常的结构与MAA选择任务一样：独立组件有自己的参数，日常只是按所选组件和顺序组合，不需要另一个前端或控制器。v1.2.5公开入口`ark.py run daily --inputs daily.json`接受`{"modules":["base","recruit","mall","award"]}`；默认不带参数的日常沿原组合不变。AI按用户要求生成配置，只调用选中项，不静默退回整套full。既有工程继续实际选定入口，不因公开版更新而自动切换本机生产。

- 保留已跑通的导航和逐关流程；按需调用 MAA 的自动战斗、选人、训练室等功能，不因为 MAA 也能做日常就反复切换整套流程。
- AI 处理陌生页面和异常；MAA 正在连续操作时，AI 不同时点击。
- MAA 刚启动时遇到更新可先更新；日常已开始后选“稍后/否”，下次日常启动再更新。更新后的人工设置指引可通过实际“跳过”控件或已验证配置方法跳过，不能误当成账号首次接入流程。
- MAA 更新后按[版本衔接检查](references/maa-update-compatibility.md)核对公告、实际接口与本 Skill，改过时的说明和失效接缝；不因 MAA 新增同类能力就重写稳定流程，也不把 MAA 的 OCR 升级误当成 Python OCR 已升级。
- 模拟器路径、实例、ADB 端口和游戏渠道由接收方本机确认。本 Skill 的游戏画面采用横屏 `1920×1080`，不直接复制作者机器的路径或端口。

## 开始和接续任务

每项能力是独立模块，日常只是这些模块的一个组合。用户可以单独调用、插入、调整顺序和参数；模块只返回自己的结果，不顺带启动后续业务或关游戏。共用环境准备和最终补领由调用方安排，做完单项不等于做完全部任务。实际调用见[模块独立调用与组合](references/continuity-and-signin.md#模块独立调用与组合)。

1. 完整包先用 `runtime/ark.py list` 找任务入口；已有工程沿当前 `AGENTS.md` 和配置。用实际工程路径，不整读历史，也不要求新接收方先建立作者那套Loop。
2. 新接入时按[首次功能设置](references/first-run-features.md)确认账号、资源和可选功能；已有账号直接沿用已确认设置。公开默认日常链保持原发布版，不要求用户重新拼装。
3. 先确认是否已经有脚本执行这次任务。有就接着它做；中断后核对已经产生的游戏效果，只补没做完的部分。窗口打开或命令退出成功不代表游戏任务完成。
4. 按[账号进度](references/account-progress.md)读取本账号已验证的结果，完成后更新同一账号。用户手动完成的只跳过对应项，不能冒记为自动化成果。
5. 同一次任务没有变更时，复用已确认的配置和检查结果，只读最新进展。不要每走一步都重读启动器、整份交接或长聊天。缺少初始配置时参考[配置示例](templates/PROJECT_CONTRACT.example.json)；资源与完成标准详见[运行约定](references/runtime-contract.md)。
6. 模块返回、修复/人工接回、转刷材料和最终收尾时，按[下一步校核](references/continuity-and-signin.md#接回后先判断下一步是否还合适)比较旧队列与最新用户要求：无变化继续，有变化只调整相关未完项，不重放已完成内容，也不新增审批等待。单项模块不顺带开启整日日常或新战斗。

恢复时先用几句话认清：当前用户要做什么、哪些已经完成、下一步用什么入口、什么时候结束。用户后来的纠正覆盖相关旧要求，不按对话标题猜任务，也不为了保险重新设计一套控制器。已有下一动作就实际执行；只有遇到具体缺口才查相关文档或代码。

已包含 `tools/daily_execution_brief.py` 的工程，日常运行中可用`--focus`；带卫戍任务视图的版本用`--task spa --focus`，不会自动切入日常。简报只提供当前运行、截图路径和下一步，不是新的审批条件。没有此工具/参数的版本直接读当前任务记录，不为升级工具阻塞原任务。使用接收方已配置的项目Python；PowerShell命令交给PowerShell，解释器已确定后不再搜索或试不明来源的裸`python`。

## 按任务查对应说明

- 启动与已接入的页面轮询默认复用无损截图缓冲；不建日志相册。想用 AI 打高难关的用户可选[重复失败复盘与卫戍角标（待测试）](references/hard-trial-review.md)，不影响默认日常。

- **按自在道爷的挂机阵容选模组**：先运行 `python scripts/select_module_presets.py` 看推荐顺序和作业号。用户选了哪些才加入本账号，默认只开一阶；也可不用这个库。见[选择模组并入队](references/operator-and-voucher-interfaces.md#选择模组并入队)。

- **打一个未通过的悖论模拟（Beta）**：含此功能的完整包在 `runtime` 目录运行 `python ark.py run paradox`，不需要指定干员或作业号。见[悖论模拟](references/paradox-simulation.md)。

只读本次用得上的说明，不要求每轮全部加载。

- 接收方首次对接、介绍功能或检查漏接模块：[功能总览与调用地图](references/capability-map.md)。MAA 原生不支持，不代表本 Skill 没有补充功能；文件存在也不代表已经接入。
- 换电脑、改模拟器/MAA/Python 路径、ADB 连接或显示尺寸：[Windows 环境接入](references/windows-portability.md)，先做已有的只读环境检查。
- 日常、推图、理智使用、最终领奖与退出：[日常与活动流程](references/workflows.md)。当期逐日开放的附加任务也归这里；未配置的可选模块不阻塞原有日常。
- 保全派驻独立模块（内部自动编队→战斗→结算与周期领奖）：[保全编队桥接](references/sss-formation-bridge.md)。AI 按作业和账号生成选人配置，脚本调用 MAA 编队后接着执行保全作业；编队底层接口只供内部测试/恢复，不作为用户需要单独选择的目标。
- 肉鸽积分奖励、永久加点、月度队伍、调查任务和整轮结算后处理：[肉鸽奖励](references/roguelike-rewards.md)。
- 生息演算繁荣点数领奖：读同一份[肉鸽与生息领奖说明](references/roguelike-rewards.md)中的生息部分。刷分和兑换是前后两步；单独领奖不自动开始刷分或重置存档。
- 卫戍协议「规程」刷取和积分奖励：[卫戍协议](references/stronghold-protocol.md)。首次教学不一定每次出现；刷取已实测，自动兑换仍有 Beta 待接入部分，不能说已能自动清店，也不要另造购买审批。
- 多主题肉鸽、反复败关截图和策略研究扩展：[肉鸽模式与扩展](references/roguelike-mode-and-extension.md)。默认只收集证据和建议，不自动改战斗策略。
- 已完成项目重复检查、跨任务记住账号进度：[账号进度](references/account-progress.md)，使用 `scripts/account_progress_v1.py` 保存本账号实测结果；它不替代游戏内核实。
- 干员培养与凭证兑换：[可选模块、参考方案和实际接口](references/operator-and-voucher-interfaces.md)。培养可选升级、专精与模组，参考近期自在道爷挂机流，也可替换自己的目标；先查实际，只补未完。未选不影响日常，未接入部分标Beta。
- MAA 错误、模拟器退出、更新、剧情、队列卡住、解释器或重复控制器：[故障恢复](references/recovery-playbook.md)。
- 中断续跑、用户手动完成、签到新样式或陌生页面：[中断续跑与签到](references/continuity-and-signin.md)。用户没有回复不撤销已经交代的任务。
- 没有兼容作业的教学关：[教学关 AI 操作](references/tutorial-ai.md)。AI 先按当前部署/朝向提示尝试，确实解决不了再请用户；对外名称为“教学关代理逻辑（测试）”。
- OCR 冲突、奖励/状态误判、理智与战斗记录不符：[结果核验](references/evidence-validation.md)。先找产生错误的环节，不直接换模型或重打游戏。
- 更新提示及用户要求升级：[更新提示与保留本地修改](references/release-notices-and-local-merge.md)。每日只在现有报告附加版本提示，用户决定是否让自己的 AI 合并更新，不自动覆盖。
- 修改脚本：在实际工程修复，重测出错图片和真正运行的入口。只改报告/识别可复用已有游戏证据；改点击或导航要在获准的实机流程验证。游戏正常运行时只做必要诊断，不开第二个控制器或同时跑大规模测试。只有说明没有运行模块时，明确缺少模块，不能声称执行成功。

## 画面和结果怎么核对

本 Skill 自己的坐标和裁剪区按游戏原始截图横屏 `1920×1080` 使用；其他尺寸不能猜比例继续点。MAA 内部识别用的 `1280×720` 缩放图是正常现象，不能拿它的坐标直接点原始游戏画面。

证据冲突时，优先核对游戏当前原图/结算，其次是对应本次运行的 MAA 回调，再看脚本记录。进程和窗口存在只说明程序在，不证明任务完成；`TaskChainError` 也不直接等于战败。把事实、推测和待验证结果分开写。

恢复按实际情况处理：

- 正常战败或探索结束：按原定重试/结算策略继续，不当成技术重启理由。
- 看得懂的弹窗或误入页面：通过现有后台方法处理，确认画面变化后继续，不因字形、标点或换肤硬性中断。
- 真正的程序/连接故障：只修失败环节，先核对已发生的效果，不重放已经完成的工作；保留还能使用的游戏环境。
- 当前还看不懂：保存新图，只暂停依赖该页面的动作。AI 可按实际可见控件接回，不必等每种弹窗都有专用脚本；无法处理的说明留给用户，其余独立任务继续。

不擅自改变主题、难度、干员、药石使用或重试上限。兼容主页皮肤时先找已有模板和路径，不把修识别变成更换用户主题。

## 结束时

日常做完后又追加肉鸽或其它任务的，追加任务结束后仍要检查新完成的招募、基建产出和任务奖励，再按原约定退出。只补新待办，不重排整套基建、不重跑五链，也不因理智还有余额自动开始刷材料；具体调用见[追加任务后的补领](references/continuity-and-signin.md#追加任务结束后只补新待办)。

用人话说明做完了什么、哪些没做完、还在跑什么以及游戏是否已关闭。完成证据不足就说未确认，不拿测试通过或消息已送达代替游戏完成。已有项目记录就更新原记录，只有查明原因的错误才写成可复用经验；没有项目 Loop 的接收方不必为此新建一套管理文件。
