# 脚本与 AI 协作：保现场、只续原步骤、到点收尾

适用于接收方已对接协作接口的长跑宿主。固定的领奖、成长加点、批量代理、每日任务继续由已有模块执行；AI 只处理需要判断的异常，不逐次接管稳定动作。本附件说明协作契约；相关既有执行代码见 `../runtime/ark_host/cooperation_v1.py`，接收方仍需绑定自己的宿主消息接口，不提供独立的无人值守唤醒服务。

## 异常不能把控制权与截止一起丢掉

已知恢复仍走原模块；普通探索战败不是程序故障。未知或恢复失败时暂停受影响步骤，保留宿主进程、控制锁、run 身份与硬截止，不先关闭游戏再等 AI。消息或状态写入失败也不能取消截止检查；等待期间不写业务完成。

宿主生成最小反馈：同 run/事件身份、失败步骤、当前状态、队列是否空闲、新鲜截图或日志位置、worker 存活与截止。只在空闲时取不会干扰战斗的只读证据。执行对话承接原终端输出；有反馈后先核对准确 run 并投递，再深入诊断，不等待宿主退出，也不反复查询父子进程才通知。

文件或 `ARK_NEEDS_ATTENTION` 输出只表示待投递。只有原生消息工具确认成功才记送达；失败可以重投同一事件，不能重放游戏动作。对话退出、模型不可用时保留 pending，宿主仍须到点收尾；没有独立验证过的后台机制，不宣称可以自动唤醒 AI。

## 回复与恢复是两件事

接口只接受有限意图（例如复核、边界暂停、边界停止），不接收任意代码或命令。回复绑定准确 run 和事件，拒绝旧回复、异 run、已结束 run。

复核请求写入后仍是待应用，不等于问题已解决。宿主重新读取队列与页面，确认安全前提后只重试原失败步骤，保留已完成效果和累计资源/战斗预算。队列忙、页面不符或修复未成立时继续等待或按合同报告，不能强行放行。

需要修改代码时，在隔离候选中修复并验证；运行中的 Python 不会因磁盘源码变化自动加载新实现。若无法回到原调用点，保留等待和截止，另建获准的有界续接，不把本方法宣传成任意异常热修复。

## 暂停、停止与清理

在结算后或下一轮 Core 开始前由同一宿主读取暂停/停止请求，不靠 AI 抢几秒间隔，不打断尚在执行的整轮探索。等待期间新到的暂停请求不能丢；停止仍受队列安全边界约束，硬截止优先。

截止和收尾预留沿原任务，不因等 AI 延长。清理只作用于本 run 拥有的环境，核实实例、MAA、控制器与临时配置恢复；不能以进程退出码 0 代替清理证据。Core 内部尚未返回的卡死，需要该层另有可验证的看门能力，不能由外层等待机制推定已解决。

## 长期复核怎样退场

接收方可按风险沿既有项目采用能力/版本粒度的稳定性门槛。本项目当前门槛是：相关能力连续三次无程序错误的真实执行，且改动分支确实触发后，才从项目/执行平行复核交给执行侧单路。计数复用原 run 证据，不另造调度或台账，不为凑次数重复业务。

验收对象是程序正确执行与修复分支效果，不是关卡输赢。离线测试、三次看同一画面、未触发的异常分支或只完成三轮探索，都不能自动视为某项修复三次通过；游戏未通关仍须如实保留。后续相关变更重新验证受影响范围，不能用旧版本成功覆盖。

## 截至 2026-10-28 的证据边界

| 能力 | 已有证据 | 不能外推 |
| --- | --- | --- |
| 异常反馈与原步骤续接 | 受控故障下，真实游戏页面、存活宿主、原生消息、AI 回复、新鲜核验、原奖励函数仅实际执行一次 | 自然复杂异常均可自主修复、秒级通知 |
| 暂停与无人回复收尾 | 下一轮 Core 前暂停，故意不回复，按缩短的测试截止清理；相关离线回归 112 通过、2 项历史图片缺失跳过 | Core 内部卡死、任意长期无人值守稳定性 |
| 正常银凇续跑与停止 | 随后三轮自然结算，末轮奖励可领变已领取、文化 43/43、请求停止后清理已核实；三轮零通关 | 三次通关、当天新增成长加点、异常分支三次通过 |
| 正常每日真实入口 | 同一启动器解析当前选择后，一次正常日常已完成业务与清理 | 新活动、所有专项或全新独立总控全部通过 |

上述是作者工程的限定验证摘要，不是接收方的安装验收。通知曾出现约两分钟响应与晚于收尾的投递；后续简报提速有离线检查，但端到端延迟改善仍待自然事件。所有私人截图、日志、账号与运行回执均未随包公开。
