# 活动、签到与中途接手
`python ark.py run activity-rewards` 只处理当前有效活动的奖励，不开始战斗。普通登录配给认标题和勾选按钮即可，奖励内容会变化，不要求固定物品名。

活动签到可能是登录弹窗，也可能在首页左上活动标签。先判当期开放时间和实际入口；入口撤掉且活动已结束，就跳过，日报不列签到。许愿墙按当期界面要求的标签数选择；没显示可补领时，不把旧漏领写成已补。领取按钮消失、奖励页状态变化或实际到账才算领到。

<a id="take-over-an-unfinished-step-in-place"></a>
## 页面与预期不同
先区分过渡帧、可安全关闭的说明弹窗和涉及购买、补理智或放弃进度的确认框。文字有异体或标点差异时，先对按钮区域放大重读；仍不明确时交当前执行 AI 看现场，不把一个签到页的问题扩大为整日日常失败。不要靠反复重进首页证明领奖。

## 接回后先判断下一步是否还合适
回到已确认的当前目标就从这里继续；用户改了目标则按新要求处理。活动有独立附加玩法时，按每日解锁分别核对；例如[报纸排版](workflows.md#committee-live-visual-takeover)。

## 追加任务结束后只补新待办
追加玩法不重跑已经结束的日常；收尾只补新出现的事项。见[中断与退出](continuation-and-closeout.md)。
