# 同 run 账本、记录与报告更正

用于“动作已做但记录失败”“最后队列与整轮结果冲突”“总计正确但活动详项仍取末批”等问题。只有真实效果证据成立才可以更正，不能用整理报告的名义提高业务完成度。

## 分开五个结果域

| 结果域 | 必须证明什么 | 常见错误推断 |
| --- | --- | --- |
| 业务效果 | 本轮实际完成了哪些战斗、生产、领取或周期目标 | 进程结束、GUI没勾Fight，所以整轮没战斗 |
| 完成记录 | 有效证据被原子保存，并经目标消费器读回 | 写文件成功，所以游戏目标一定完成 |
| 退出领取 | 本次明确要求的退出服务已实际处理、返回到要求页面 | 奖励展示关闭，所以所有独立奖励都领完 |
| 环境清理 | 本流程拥有的实例、队列和相关资源已核实释放 | 业务成功，所以清理也一定成功 |
| 报告投影 | JSON、总计、细项与通知来自同一有效事实 | 账本正确，所以所有文案肯定自动正确 |

各域独立保留成功、失败、未执行和未知。某个记录器失败不抹掉已证实的游戏效果，但也不能让未执行的退出领取变成已完成。

## 事实账本的身份和计数

- 绑定同一个运行、游戏日、操作对象和当前授权范围。其他运行的同日累计是另一口径，不能塞进本轮总数。
- 先按 MAA 结算会话归集，再汇总。同设备标识/任务编号可能跨进程复用，应结合进程和会话边界；轮转重叠事件去重。
- 请求了多少次、最后一批统计、旧库存和首末余额净差，都不能替代整轮实际结算。
- 保留原始 GUI 队列状态，同时另列带来源和范围的业务效果。最终每日队列没有 Fight 不代表前序会话没有战斗。
- 战斗扣除、退款和最后截图实读分别存储。只承认有来源的退款；余额差额没有直接证据就保持未解释，不能自动命名为自然恢复。
- 整轮起点、各资源分段起点和最终余额分域保存。进入后一个理智模块可以读取新起点供该段决策，但不得覆盖同 run 最早的有效起点；整轮结算也不能减去末段起点来算净差。上一 run 的起点不可带入。
- 保留取证时间、覆盖范围、来源指纹以及是否已闭合对账。缺失不是零，候选不是验证，记录时间不是效果发生时间。

本轮统计不能自动扩张到尚未覆盖的模式。例如某套聚合器只支持 Fight/剿灭结算，不得据此宣称 Copilot 或长期探索全部可对账。

## 完成记录失败后的处理

1. 先核实游戏目标是否实际完成，所需奖励/周期域是否齐全；只修写入缺陷，不重新战斗。
2. 对同一对象采用稳定幂等身份；写临时文件后原子提交，保存来源哈希，避免半文件被消费。
3. 用真实消费器重新读取并核对范围、时效与目标，不能仅验证 JSON 能解析。
4. 写入仍失败就保留记录失败；退出领取与清理按各自授权继续并独立结算，不能因为缓存异常直接跳过正常尾链。
5. 周期缓存仅在来源有效、目标已验完成且未到当前适用刷新点时短路；不把某一历史周期数值或日期复制为接收方常量。

## 假阴性与来源绑定更正

只有在根因明确且正面证据完整时，才生成派生更正。更正需绑定原 manifest、报告及必要原始证据的指纹，注明修复的具体验收器/投影问题和适用范围。原始 partial、日志和报告保留，不倒写历史。

读取更正时重新验证来源与必要业务事实。源变了、会话不闭合、缺关键回调、证据来自异队列，均不能消费为已完成。人工写一个 `completed` 标签不是证据。

原效果已封口后，更正只改变有证据支持的记录和报告结论，新增游戏动作仍为零。若还存在独立未完目标，沿现有续接机制处理，不借更正扩大权限。

## 所有出口都从同一事实投影

把规范 JSON 字段、日报总计、每项活动细节和单次最终通知逐一接到同一已对账账本，避免总计读整轮而细项仍读 `last_batch`。原始片段仍保留其“末批”含义，不改名冒充整轮。

组合测试至少同时检查：

- 多会话、多批次和轮转重叠下，规范总计与细项一致；
- 最终 GUI Fight 未选中时，前序真实战斗仍存在；
- 有效记录写入失败不触发新的战斗，退出领取和清理不会被异常吞掉；
- 单项与完整流程的不同装配顺序，都调用相同规范验收器；
- “已实际加速但仍有少量余量”和“全部耗尽”是两个判断，不以余量非零判从未加速；
- 无来源的余额差额、过期证据、未闭合会话、异队列、跨日和坏聚合不被修正成成功；
- 已发送过最终报告后，只提供必要更正，不为修改文字再次开游戏或重弹整个流程。

离线回放和零动作接线只证明对应测试边界。下次自然运行另验新源码组合，不重放已完成当天。参见 [模块化架构与迁移](modular-architecture.md) 与 [续接和真实收尾](continuation-and-closeout.md)。
